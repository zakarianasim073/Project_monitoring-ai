## 2025-05-15 - Optimizing Bill Creation and BOQ Distribution
**Learning:** The `Project` model in this application acts as a root aggregate with many large sub-document arrays. Using `findById` triggers full hydration of these arrays, which is inefficient for simple existence checks. Additionally, updating BOQ items in a loop with `.save()` creates an N+1 query problem, significantly slowing down bill processing as the number of BOQ items grows.
**Action:** Use `Model.exists()` for presence validation and `updateMany` with atomic operators like `$inc` for bulk updates to eliminate N+1 overhead and minimize database roundtrips.

## 2026-05-16 - Advanced Atomic Orchestration in DPR Creation
**Learning:** Even with atomic updates, multiple sequential `updateOne` calls on the same root aggregate (like `Project`) can be consolidated into a single operation by collecting IDs during the execution flow. Furthermore, N+1 loops for sub-resource updates (like `Materials`) can be completely eliminated using `bulkWrite` combined with aggregation pipelines to handle complex logic like stock clamping (avoiding negative stock) without read-before-write.
**Action:** Collect resource IDs for a final consolidated `updateOne` on the root aggregate. Use `bulkWrite` with `$max` and `$subtract` in an aggregation pipeline for atomic, conditional updates of multiple related documents in a single roundtrip.
